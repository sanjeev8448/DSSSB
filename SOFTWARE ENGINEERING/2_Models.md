These four models are important for understanding how software development is organized. For exam preparation, focus on phases, advantages, disadvantages, suitability, and differences between Waterfall, Prototype, Spiral, and Agile.

## 1. Waterfall Model

![SDLC (Software Development Life Cycle) Phases, Process, Models - Complete guide - scmGalaxy](https://images.openai.com/static-rsc-4/0TvU0_DAm_Pk_fI4Q2ov-tuAPJrOCtEDk8tMWFVI_zGdsG_gopP2G5hHV04pH96K-qX4FkftM5iU-skHA1jIJLZuZCjOksnW90H0m5--OgAiNVmM4uIFIITzuUSmBxgoLCCBa4-UmL9-dtpfavqyhWollOveSBr4EfcFDNPbrZ0?purpose=inline)

[scmgalaxy.com](https://www.scmgalaxy.com/tutorials/sdlc-software-development-life-cycle-phases-process-models-complete-guide/)

The Waterfall Model is a traditional SDLC model in which development proceeds through a sequence of phases. Each phase is generally completed before the next phase begins.

### Phases

1. Requirement analysis
    
2. System design
    
3. Implementation (coding)
    
4. Testing
    
5. Deployment
    
6. Maintenance
    

### Example

A government department needs a payroll system with clearly defined requirements and formal documentation. The development team finalizes requirements, designs the system, writes the code, tests it, and then deploys it.

### Advantages

- Simple and easy to understand.
    
- Clear phases, milestones, and documentation.
    
- Easier to plan when requirements are stable.
    
- Suitable when formal approvals and documentation are important.
    

### Disadvantages

- Changes can be costly after a phase is completed.
    
- Working software may appear relatively late.
    
- User feedback during development may be limited.
    
- Risks may be discovered late.
    

Best suited for: Projects with stable, well-understood requirements and limited expected changes.

Exam keyword: Sequential development.

## 2. Prototype Model

![A Deep Dive into Prototype Model in Software Engineering | Relia Software](https://images.openai.com/static-rsc-4/VbHUJkFh7ht94EljfSTEBDtAcU82gz0pzjY-LFIAbkTMSnzwXHWb8GwTNQ8xVqsF9GEo5bqR8EPhNU4XtZSQswTQCAkNWKgag7rGgkQYAz6vj1aR1m7aRkQAdlSWa979puNOhVB_8a02nbQZHr16UbnlVrBsPBSpUSfLXBD5YZs?purpose=inline)

[reliasoftware.com](https://reliasoftware.com/blog/prototype-model-in-software-engineering)

The Prototype Model creates an early, simplified version of software so that users can evaluate it and clarify their requirements before the final system is developed.

A prototype may demonstrate the user interface, workflow, or selected features without implementing the complete system.

### Process

1. Gather initial requirements.
    
2. Create a quick design.
    
3. Build a prototype.
    
4. Obtain user feedback.
    
5. Refine the prototype and requirements.
    
6. Develop and test the final system.
    

### Example

A college wants a student portal but is unsure how the dashboard should look. Developers build a basic screen showing attendance, marks, and fees. Staff review it, request changes, and help clarify the final requirements.

### Advantages

- Helps clarify unclear requirements.
    
- Encourages early user feedback.
    
- Can improve usability and user satisfaction.
    
- Potentially reduces misunderstandings about the required system.
    

### Disadvantages

- Repeated changes can increase cost and time.
    
- Users may mistake the prototype for the finished product.
    
- Rushed prototype code may have poor architecture if reused without proper redesign.
    
- Scope can expand as users request more features.
    

Best suited for: Projects where requirements are unclear, especially when user interaction and interface design need exploration.

Exam keyword: Early prototype and user feedback.

## 3. Spiral Model

![6 Software Engineering Models: Which is the Best for Your Project | Lemberg Solutions](https://images.openai.com/static-rsc-4/4auTewEIreGPhN-r6ELbn-vo-xT6IAmZdp2S1JKQXqOZynhKKUeLxpGfqiO0U8vQq_s9HuEMuoox1N2ajYjOS4qV3VlrUWXRLXYqWXFuhYXagaZLvzGjcZNhhE0keQbVnvAV_UWrk3Xcxg7TGZMh3TZofoX1WfVtAmmlqsS942o?purpose=inline)

[lembergsolutions.com](https://lembergsolutions.com/blog/6-software-engineering-models-which-best-your-project)

The Spiral Model is a risk-driven software development model in which the system is developed through repeated cycles, called spirals. Each cycle involves planning, risk analysis, development, and evaluation.

### Four main activities in a spiral cycle

1. Planning: Identify objectives, alternatives, and constraints.
    
2. Risk analysis: Identify and evaluate risks; use prototypes or experiments where useful.
    
3. Engineering: Develop and test the next version of the software.
    
4. Customer evaluation: Review the results and plan the next cycle.
    

The exact activities can vary by project, but risk analysis is the defining feature of this model.

### Example

A banking organization develops a large online banking platform. Before investing heavily in each feature, the team assesses security, data loss, transaction failure, and performance risks. It then develops and evaluates the system through successive cycles.

### Advantages

- Strong emphasis on risk identification and management.
    
- Supports changing requirements.
    
- Enables early evaluation of high-risk features.
    
- Suitable for large, complex projects.
    

### Disadvantages

- Can be expensive and time-consuming.
    
- Requires expertise in risk assessment.
    
- Management is more complex than in simpler models.
    
- May be unsuitable for small projects with low risk.
    

Best suited for: Large, complex, expensive, or high-risk software projects.

Exam keyword: Risk analysis.

## 4. Agile Model

![9 Software Development Life Cycle (SDLC) Models, Visualized](https://images.openai.com/static-rsc-4/wWpJtQ3lV3lhf4MTPY6Zd9rj2XkpVDgIRkOiOLKt4MxzLhRX1g5WREdsko5E59-vrzIHtVkqfOge82ZHOSUTm1XtPSwOo9JLKcS_C7FxTb_XEt8OBaHGtxc-Gg6YPQb_nGmVTCcZcp3r_9tDLKSv-xBZ7axInotNzIK6eMRLWJE?purpose=inline)

[scnsoft.com](https://www.scnsoft.com/software-development/software-development-models)

The Agile Model is an iterative and incremental approach to software development. Software is developed in small increments, with frequent feedback and adaptation to changing requirements.

Agile is an umbrella approach that includes methods such as Scrum and Extreme Programming (XP).

### How Agile works

1. Collect and prioritize requirements.
    
2. Select a small set of features for an iteration or sprint.
    
3. Design, develop, and test those features.
    
4. Demonstrate the working increment and collect feedback.
    
5. Review the process and plan the next iteration.
    

In Scrum, a sprint is a fixed-length iteration, commonly one to four weeks.

### Example

An e-commerce team initially releases product search and product listings. In later iterations, it adds cart functionality, payments, order tracking, and customer feedback based on priorities and user input.

### Advantages

- Adapts well to changing requirements.
    
- Delivers working software frequently.
    
- Encourages customer collaboration.
    
- Defects and misunderstandings can be discovered earlier.
    
- Progress is reviewed regularly.
    

### Disadvantages

- Requires frequent collaboration and stakeholder feedback.
    
- Scope, cost, and delivery dates can be harder to predict when requirements change continuously.
    
- Documentation or architectural planning may suffer if neglected.
    
- Less suitable when frequent changes or close collaboration are impractical.
    

Best suited for: Projects with evolving requirements, frequent releases, and regular user feedback.

Exam keyword: Iterative development and adaptability.

## 6. Scenario-based questions: Identify the model

Scenario A

Requirements are finalized at the beginning, and each phase is completed in sequence.

Answer: Waterfall

Scenario B

Users are uncertain about the required screen layout, so developers create an early version and collect feedback.

Answer: Prototype

Scenario C

A mission-critical system requires repeated risk assessment before each major development cycle.

Answer: Spiral

Scenario D

A team releases features in short iterations and reprioritizes its work based on customer feedback.

Answer: Agile

- Waterfall → Sequential phases
    
- Prototype → Early model to clarify requirements
    
- Spiral → Risk analysis
