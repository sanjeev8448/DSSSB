# 1. What is memory management?

Memory management is the operating-system function responsible for managing main memory (RAM), allocating memory to processes, tracking its usage, and protecting each process's address space.

Its major responsibilities include:

- Allocating and releasing memory.
    
- Tracking which memory areas are in use.
    
- Translating logical addresses into physical addresses.
    
- Protecting processes from unauthorized memory access.
    
- Supporting virtual memory when the system uses secondary storage to back some virtual memory pages.
    

## Logical vs physical address

A logical address is an address generated by a program's execution. A physical address identifies a location in main memory (RAM).

The Memory Management Unit (MMU) is hardware that helps translate addresses and enforce memory protection.

|Logical address|Physical address|
|---|---|
|Generated by the executing program or CPU|Address in physical memory|
|Also commonly called virtual address in modern systems|Actual RAM location|
|Translated by memory-management hardware and OS mechanisms|Used to access physical memory|

Exam trap: In introductory questions, logical and virtual addresses are often used interchangeably. In more detailed architecture discussions, the terms can have distinct meanings depending on the system.

# 2. Contiguous memory allocation

In contiguous memory allocation, each process is assigned one continuous block of physical memory.

For example, suppose a process requires 100 KB of memory. The OS allocates a suitable contiguous region large enough to hold its memory image.

### Example of contiguous allocation

Operating system

Process P1 — 100 KB

Process P2 — 150 KB

Free memory

Illustrative physical-memory layout; each process occupies one contiguous region.

## A. Fixed partitioning

In fixed partitioning, memory is divided into partitions of predetermined sizes. Each partition can hold at most one process at a time.

For example, if a 100 KB partition holds a process of 70 KB, the remaining 30 KB inside that partition cannot generally be allocated to another process while the partition is occupied.

This is an example of internal fragmentation.

Advantages: Simple to implement.

Disadvantages: Fixed partition sizes can waste memory and limit how many processes can be loaded simultaneously.

## B. Variable partitioning

In variable partitioning, memory regions are allocated dynamically according to process requirements.

For example, a process requiring 75 KB may receive an appropriately sized region of about 75 KB, subject to allocation rules and metadata overhead.

This can reduce the internal waste associated with fixed partitions, but it can create external fragmentation as free memory becomes split into separated holes.

## C. Memory placement algorithms

These algorithms decide which available free block (hole) to use for a process.

### First Fit

Allocate the first free block that is large enough.

Suppose free blocks are:

`100 KB, 500 KB, 200 KB, 300 KB`

A process requesting 180 KB receives the 500 KB block under First Fit, because the first 100 KB block is too small.

### Best Fit

Allocate the smallest free block that can accommodate the process.

Using the same blocks, a 180 KB request would be assigned to the 200 KB block.

### Worst Fit

Allocate the largest free block available that can accommodate the process.

The 180 KB request would be assigned to the 500 KB block.

|Algorithm|Selection rule|Typical concern|
|---|---|---|
|First Fit|First sufficient block|May leave many small holes in some workloads|
|Best Fit|Smallest sufficient block|Can create many tiny unusable holes|
|Worst Fit|Largest sufficient block|May break up large useful blocks|

Performance depends on the allocation pattern. Do not assume one algorithm is always best for every workload.

Exam memory trick: First = first suitable; Best = smallest suitable; Worst = largest suitable.

## D. Base and limit registers

Classic contiguous allocation can use a base register and a limit register.

- Base register: Starting physical address of the process's allocated region.
    
- Limit register: Size of the permitted logical address range.
    

For a valid logical address \(LA\):

\[ \boxed{PA=Base+LA} \]

The address must also satisfy:

\[ 0\leq LA<Limit \]

### Example

Suppose:

- Base = 4000
    
- Limit = 1000
    
- Logical address = 200
    

Then:

\[ PA=4000+200=\boxed{4200} \]

The access is valid because \(200<1000\).

If the logical address were 1200, the access would be invalid because it exceeds the permitted range.

# 3. Paging

Paging is a memory-management technique that divides a process's logical address space into fixed-size pages and physical memory into equally sized frames.

A page can be loaded into any available frame. Therefore, a process does not need one contiguous block of physical memory.

- Page: Fixed-size block of a process's logical memory.
    
- Frame: Fixed-size block of physical memory.
    
- Page table: Data structure used to map pages to physical frames.
    

Page size and frame size are equal.

## A. Paging address calculation — very important

A logical address is divided into two parts:

\[ \boxed{\text{Logical address}=(\text{Page number},\text{Offset})} \]

The page number identifies the page, and the offset identifies a position within that page.

For a page size \(S\) and logical address \(LA\), using zero-based byte addresses:

\[ \boxed{\text{Page number}=\left\lfloor\frac{LA}{S}\right\rfloor} \]

\[ \boxed{\text{Offset}=LA\bmod S} \]

After looking up the page number in the page table:

\[ \boxed{PA=(\text{Frame number}\times S)+\text{Offset}} \]

### Numerical example

Suppose:

- Page size = 1024 bytes.
    
- Logical address = 2500.
    
- Page 2 maps to frame 7.
    

Step 1: Calculate the page number.

\[ \left\lfloor\frac{2500}{1024}\right\rfloor =\boxed{2} \]

Step 2: Calculate the offset.

\[ 2500\bmod1024=\boxed{452} \]

So the logical address is page 2, offset 452.

Step 3: Find the frame number.

From the page table, page 2 maps to frame 7.

Step 4: Calculate the physical address.

\[ PA=(7\times1024)+452 \]

\[ PA=7168+452=\boxed{7620} \]

Therefore, the physical address is 7620.

## B. Page size and offset bits

If the page size is a power of two:

\[ \boxed{\text{Offset bits}=\log_2(\text{Page size in bytes})} \]

For a page size of 4096 bytes:

\[ 4096=2^{12} \]

The offset requires 12 bits.

If the logical address is 32 bits, then:

- Offset = 12 bits.
    
- Page number = \(32-12=20\) bits.
    

This would allow \(2^{20}\) logical pages in that 32-bit address format, subject to the system's actual address-space design.

## C. Advantages of paging

- Eliminates external fragmentation of physical-memory allocation in the standard paging model.
    
- Allows pages to be placed in noncontiguous frames.
    
- Supports virtual memory and page-level protection.
    
- Simplifies physical-memory allocation using fixed-size frames.
    

## D. Disadvantages of paging

- Page tables consume memory.
    
- Address translation adds work, although hardware such as a TLB can accelerate it.
    
- The final page of an allocated region may be only partly used, producing internal fragmentation.
    
- Accessing a page not currently resident in RAM may trigger a page fault.
    

Exam trap: Paging eliminates external fragmentation in the standard model, but it does not eliminate internal fragmentation.

# 4. Segmentation

Segmentation divides a program's logical address space into variable-sized logical units, such as code, data, stack and procedures.

Unlike paging, segmentation uses variable-sized segments based on logical program organization.

Examples of segments include:

- Code segment.
    
- Data segment.
    
- Stack segment.
    
- Heap or other logically distinct program regions, depending on the model.
    

## A. Logical address in segmentation

A logical address is represented as:

\[ \boxed{(\text{Segment number},\text{Offset})} \]

Each segment-table entry typically provides:

- Base: Starting physical address of the segment.
    
- Limit: Length of the segment.
    

The offset must be within the segment limit:

\[ 0\leq Offset<Limit \]

Then:

\[ \boxed{PA=Base+Offset} \]

### Numerical example

Suppose segment 2 has:

- Base = 5000
    
- Limit = 1000
    

A logical address references segment 2 with offset 300.

Since:

\[ 300<1000 \]

the address is valid.

Physical address:

\[ PA=5000+300=\boxed{5300} \]

Now suppose offset = 1200.

Because:

\[ 1200\geq1000 \]

the offset is outside the segment's limit, so the access is invalid.

## B. Advantages of segmentation

- Matches logical program structure.
    
- Provides a natural way to support protection and sharing by segment.
    
- Allows segments to have different sizes.
    
- Can make it easier to assign different access rights to code, data and stack segments.
    

## C. Disadvantages of segmentation

- Variable-sized allocation can cause external fragmentation.
    
- Allocation and management are more complex than using fixed-sized pages.
    
- Finding suitable contiguous physical space for a growing segment can be difficult.
    

## D. Paging vs segmentation

|Feature|Paging|Segmentation|
|---|---|---|
|Division|Fixed-size pages|Variable-size logical segments|
|Division basis|Memory-management units|Logical program structure|
|Logical address|Page number + offset|Segment number + offset|
|Mapping structure|Page table|Segment table|
|Physical placement|Pages map to individual frames|Each segment generally occupies a contiguous region in classic segmentation|
|Fragmentation|Internal fragmentation possible; standard paging avoids external fragmentation|External fragmentation possible|
|Programmer visibility|Usually transparent to the program|Segments can represent visible logical program units|

Memory trick: Paging = fixed-size blocks; Segmentation = variable-sized logical units.

# 5. Virtual memory

Virtual memory is a memory-management technique that allows processes to operate within a virtual address space without requiring all of their pages to be resident in physical RAM simultaneously.

The OS and hardware map virtual addresses to physical memory and can use secondary storage as backing for portions of virtual memory.

For example, a process may have a virtual address space larger than the amount of RAM currently available to it. Only the needed portions have to be resident, subject to OS and hardware constraints.

## A. How virtual memory works

### Virtual memory overview

Process virtual address space

Pages used by the program

MMU + page tables

Translate virtual addresses

RAM

Resident pages

Backing storage

Pages not currently resident

When a required page is absent from RAM, page-fault handling may bring it into memory.

### Advantages of virtual memory

- Allows a process to use a large virtual address space.
    
- Improves flexibility in RAM utilization.
    
- Can support more concurrent processes than would fit if each required its entire address space in RAM.
    
- Provides address-space isolation and protection when supported by the OS and hardware.
    

### Disadvantages

- Page faults can be expensive because disk or other backing-storage access is much slower than RAM.
    
- Page tables require memory.
    
- Poor memory-management behavior can cause excessive paging and severe performance degradation.
    
- Virtual memory does not guarantee that every program will run regardless of its memory requirements or available storage.
    

Exam trap: Virtual memory is not the same as virtual RAM being physically present in a disk. It is an address-space abstraction backed by physical memory and, when necessary, other storage or OS-managed mechanisms.

## B. Demand paging

Demand paging loads a page into RAM when it is first needed, rather than loading every page in advance.

Conceptually:

1. The process refers to a virtual page.
    
2. The hardware checks the page-table entry.
    
3. If the page is resident, access proceeds after address translation.
    
4. If the page is not resident, a page fault occurs.
    
5. The OS locates or creates the required page contents and prepares a physical frame.
    
6. The page-table entry is updated.
    
7. The instruction is restarted or resumed as appropriate.
    

This avoids loading pages that may never be used, but page faults introduce overhead.

# 6. Page fault

A page fault occurs when a process accesses a virtual page that requires operating-system handling because the reference cannot be completed directly using the current page-table state.

In the basic demand-paging model, the page is not currently resident in RAM, so the OS must fetch or otherwise make the page available.

### Important: Is every page fault an error?

No. A page fault is a hardware-detected event that transfers control to the OS. It may be a normal part of demand paging.

A page fault can be resolved successfully if the reference is valid and the OS can bring the needed page into an appropriate memory frame.

If the process accesses an invalid address or violates access permissions, the OS may instead signal an exception or terminate the process.

## Page-fault handling steps

1. The CPU references a virtual address.
    
2. The hardware detects that the required access cannot proceed using the current translation state.
    
3. Control transfers to the page-fault handler in the OS.
    
4. The OS checks whether the access is valid and permitted.
    
5. If valid, the OS locates the page or creates the required contents and obtains a suitable frame. If necessary, another page may be selected for replacement.
    
6. The OS updates page-table information and any needed translation-cache state.
    
7. The instruction is retried or resumed. If the access was invalid, the OS handles the fault as an error.
    

### Page fault vs page replacement

|Page fault|Page replacement|
|---|---|
|An event requiring page-fault handling|A policy or action that chooses a resident page to remove when needed|
|Can occur on a nonresident page reference|May be required during handling if no suitable free frame is available|
|Does not always require replacing another page|Is one possible part of page-fault handling|

### Page-fault overhead

Resolving a page fault can require substantial time when the page must be retrieved from storage. This is why a high page-fault rate can severely reduce system performance.

Exam trap: A page fault does not automatically imply that a program has made an illegal memory access.

# 7. Swapping

Swapping is a memory-management technique in which a process's memory image, or portions of its memory, are moved between main memory and backing storage so that RAM can be used for other work.

In the traditional textbook model, an entire process may be swapped out and later swapped back in. Modern systems commonly manage virtual-memory pages individually or in groups rather than necessarily moving whole processes.

### Traditional swapping example

Suppose RAM contains processes P1, P2 and P3. P2 is temporarily swapped out to backing storage, allowing the OS to use that memory space for another process.

### Advantages

- Frees RAM for other processes or uses.
    
- Can help the OS manage memory pressure.
    
- Allows inactive processes or memory contents to reside outside physical RAM temporarily.
    

### Disadvantages

- Storage transfers can be slow compared with RAM access.
    
- Moving large amounts of memory can cause significant overhead.
    
- Excessive movement between RAM and storage can degrade performance.
    

Exam trap: Swapping and paging are related but not identical in the traditional terminology. Swapping classically moves a process's memory image; paging transfers fixed-size pages.

# 8. Fragmentation

Fragmentation refers to memory waste caused by the way memory is allocated.

The two main types are:

1. Internal fragmentation
    
2. External fragmentation
    

## A. Internal fragmentation

Internal fragmentation occurs when the allocated memory block is larger than the amount of memory requested, leaving unused space inside the allocated block.

### Example

A process needs 18 KB but is allocated a fixed partition of 24 KB.

\[ \text{Internal fragmentation}=24-18 \]

\[ \boxed{6\text{ KB}} \]

The 6 KB is wasted inside the allocated partition.

Where it commonly occurs:

- Fixed partitioning.
    
- Paging, especially in a partly used final page.
    

## B. External fragmentation

External fragmentation occurs when free memory is divided into separated holes, so a request for a large contiguous block cannot be satisfied even though the total free memory may be sufficient.

### Example

Suppose the free holes are:

- 10 KB
    
- 20 KB
    
- 15 KB
    

Total free memory:

\[ 10+20+15=\boxed{45\text{ KB}} \]

A process requests 30 KB of contiguous memory. No single hole can satisfy the request even though 45 KB is free in total.

This is external fragmentation.

### Visual comparison

### Internal fragmentation

Unused space is inside an allocated 24 KB block.

### External fragmentation

15 KB free

Free memory exists in several holes, but no hole is large enough for a 30 KB contiguous request.

### Compaction

Compaction moves allocated blocks so that scattered free holes are combined into a larger contiguous free region, where relocation is supported.

Compaction can help reduce external fragmentation in systems using variable-sized contiguous allocation.

It does not eliminate internal fragmentation within an allocated block.

## C. Fragmentation comparison

|Feature|Internal fragmentation|External fragmentation|
|---|---|---|
|Where is memory wasted?|Inside an allocated block|Between allocated blocks, in separated free holes|
|Common cause|Allocation granularity or oversized fixed partitions|Variable-sized allocation and deallocation|
|Example|6 KB unused in a 24 KB partition|45 KB total free, but no 30 KB contiguous hole|
|Possible response|Choose a suitable allocation unit or block size|Compaction or a different allocation strategy|
|Paging|Can occur|Standard paging avoids external fragmentation of physical-frame allocation|

### Exam traps

- Fixed partitioning can cause internal fragmentation.
    
- Variable-sized contiguous allocation can cause external fragmentation.
    
- Paging can cause internal fragmentation but ordinarily eliminates external fragmentation of physical-frame allocation.
    
- Compaction can reduce external fragmentation when processes can be relocated.
    
- Having enough total free memory does not guarantee that a contiguous allocation can be made.
    

# 9. Paging vs segmentation vs contiguous allocation

This comparison is particularly useful for conceptual questions.

|Feature|Contiguous allocation|Paging|Segmentation|
|---|---|---|---|
|Memory allocation unit|One contiguous region per process|Fixed-size pages and frames|Variable-size segments|
|Address format|Base + offset in the classic model|Page number + offset|Segment number + offset|
|Mapping structure|Base/limit or equivalent|Page table|Segment table|
|External fragmentation|Possible with variable-sized allocation|Avoided for physical-frame allocation in standard paging|Possible in classic segmentation|
|Internal fragmentation|Possible|Possible, especially in the final page|Not the primary fragmentation issue in classic segmentation|
|Logical program structure visible in the allocation unit|Not necessarily|Usually not|Yes, segments can represent code, data, stack and related units|
|Noncontiguous physical placement|Not within a single allocated region in the basic model|Yes|Classic segment allocation normally keeps each segment contiguous|

## 10. Virtual memory vs swapping vs page fault

These three terms are related, but they describe different things.

|Concept|Meaning|
|---|---|
|Virtual memory|An address-space and memory-management abstraction|
|Swapping|Moving memory contents between RAM and backing storage, classically by process|
|Page fault|An event that requires OS handling when a memory reference cannot proceed using the current translation state|
|Demand paging|Loading a page when it is needed|
|Page replacement|Selecting a resident page to evict when another page needs a frame and no suitable free frame is available|

Key distinction: A page fault can occur in a virtual-memory system. If the reference is valid but the page is not resident, the OS may resolve it by bringing the page into RAM. It is not necessarily an illegal address or a system crash.

# 11. Memory Management — numerical questions to practise

### Question 1: Paging address translation

A system has a page size of 2048 bytes. A logical address is 5000. Suppose the corresponding page maps to frame 4. Find the page number, offset and physical address.

Step 1: Page number

\[ \left\lfloor\frac{5000}{2048}\right\rfloor=2 \]

Step 2: Offset

\[ 5000\bmod2048=904 \]

Step 3: Physical address

\[ PA=(4\times2048)+904 \]

\[ PA=8192+904=\boxed{9096} \]

Answer: Page number = 2, offset = 904, physical address = 9096.

### Question 2: Internal fragmentation

A fixed partition has a size of 32 KB. A process occupies 25 KB. How much internal fragmentation is present?

\[ 32-25=\boxed{7\text{ KB}} \]

### Question 3: External fragmentation

Free memory holes are 12 KB, 18 KB and 25 KB. A process needs 30 KB of contiguous memory.

Total free memory:

\[ 12+18+25=55\text{ KB} \]

No individual hole is large enough for 30 KB. Therefore, the allocation fails without suitable compaction or another memory-management strategy, despite 55 KB being free in total.

### Question 4: Segmentation address translation

A segment has base 7000 and limit 1500. The process refers to offset 400 within that segment.

Since \(400<1500\), the reference is valid.

\[ PA=7000+400=\boxed{7400} \]

If the offset is 1500, the reference is invalid because valid offsets range from 0 through 1499.

## Last-minute memory trick

- Contiguous allocation: One continuous physical block per process.
    
- Paging: Fixed-size pages and frames; use a page table.
    
- Segmentation: Variable-sized logical segments; use a segment table.
    
- Virtual memory: A process's address space need not be fully resident in RAM.
    
- Page fault: OS handling is needed for a memory reference that cannot proceed using the current translation state.
    
- Swapping: Moves memory contents between RAM and backing storage.
    
- Internal fragmentation: Waste inside an allocated block.
    
- External fragmentation: Free memory scattered across separated holes.
    

Most important numerical formulas:

\[ \text{Page}=\left\lfloor\frac{LA}{\text{Page size}}\right\rfloor \]

\[ \text{Offset}=LA\bmod\text{Page size} \]

\[ PA=(\text{Frame number}\times\text{Page size})+\text{Offset} \]

\[ \text{Internal fragmentation} =\text{Allocated size}-\text{Requested size} \]

For the exam, practise paging address calculations and internal/external fragmentation examples until you can solve them without looking at the formulas.
